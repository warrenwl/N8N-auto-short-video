### 验证结果

- Phase 1 数据库迁移可重复执行。
- `create_novel_chapter_version(..., FALSE)` 生成候选稿时不会设置 `is_current=true`。
- `approve_novel_chapter(...)` 能原子完成正式版本切换、facts 切换、人工审核记录、项目进度更新和下一章任务创建。
- `request_novel_chapter_rewrite(...)` 不依赖 `is_current=true`，只处理 `NEED_REVIEW` 候选稿。
- `reject_novel_chapter(...)` 拒绝候选稿时保持正式 current 不受影响。
- 任务领取断言覆盖了 `FOR UPDATE SKIP LOCKED`。
- continuity facts 查询规则已验证：生成/审稿第 N 章时排除同章 AI facts，但保留同章 human facts。

### 遗留风险

- `sql/49_novel_workflow_queries.sql` 仍是 n8n Postgres 节点查询片段，不是可整体执行的迁移文件；后续做 workflow JSON 时需要逐个节点绑定参数验证。
- Phase 1 未调用真实 GLM，也未验证 n8n Code 节点脚本；这些进入 Phase 2。
- 当前仅验证数据库层闭环；Webhook POST、防 GET 误触和 HTML 表单进入 Phase 2/Phase 5。
