# 小说工作流整体架构

更新时间：2026-05-02

本文档是当前 N8N Video Agent 项目里的小说自动生成工作流设计。第一版目标不是一次性写完整本小说，也不是马上做自动发布，而是先跑通一条稳定的中文连载小说生产线：

```text
小说项目创建
  -> 生成小说 Bible
  -> 生成章节大纲
  -> 逐章生成正文
  -> AI 审稿
  -> 人工审核
  -> 批准后进入下一章
```

核心原则：

- 复用当前项目的 `video_agent` 业务数据库，不单独创建 `novel_factory`。
- 复用当前项目的 n8n + PostgreSQL + GLM OpenAI-compatible HTTP 调用方式。
- 让 PostgreSQL 管状态，n8n 每次原子领取一条任务，避免并发重复执行。
- AI 审稿只给评分和建议，最终是否通过由人工审核决定。
- 章节按版本保存，后续续写只读取当前已批准版本。

------

# 一、整体架构

建议新增一条独立的 `novel_*` 内容域，不把小说数据塞进现有 `video_topics` 短视频表。小说链路和短视频链路共享基础设施，但业务表、状态机和审核页面独立。

```text
n8n
├── 工作流 11：小说项目中心
├── 工作流 12：生成小说 Bible
├── 工作流 13：生成章节大纲
├── 工作流 14：逐章生成正文
├── 工作流 15：AI 审稿
├── 工作流 16：小说审核中心
├── 工作流 17：重写章节
├── 工作流 18：小说任务自动恢复
└── PostgreSQL video_agent：保存项目、Bible、大纲、正文、审稿、事实和任务
```

核心数据流：

```text
novel_projects
  -> novel_bibles
  -> novel_chapter_outlines
  -> novel_generation_jobs
  -> novel_ai_runs
  -> novel_chapters
  -> novel_review_reports
  -> novel_human_reviews
  -> novel_project_events
  -> novel_continuity_facts
  -> novel review center
```

第一版的人工入口优先做 Webhook HTML 页面，风格参考现有 `/webhook/topic-center` 和 `/webhook/video-review-list`。Server 酱只负责提醒，不承载审核动作。

------

# 二、与当前项目的集成约定

当前项目已经有一套稳定目录约定，小说工作流沿用它：

```text
sql/
  放 PostgreSQL 迁移 SQL 和 n8n Postgres 节点 SQL 片段

config/
  novel_generation_config.jsonc
  放 GLM 模型、采样参数、题材选项、提示词模板和审核阈值

n8n/code/
  放 Code 节点脚本，例如构造 GLM 请求、解析章节 JSON、生成审核中心 HTML

n8n/workflow/available/
  放推荐启用的小说工作流 JSON
```

数据库连接继续使用 README 里的业务库：

```text
PostgreSQL 宿主机：localhost:5432
PostgreSQL 容器内：postgres:5432
业务数据库：video_agent
用户：n8n
```

不新增外部依赖，不新增独立数据库，不把 API Key 写进 Markdown、workflow JSON 或 SQL。GLM API Key 继续从 `.env` 或 n8n Credentials 读取。

# 三、PostgreSQL 数据库设计

## 1. 基础扩展和更新时间函数

```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;

CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = NOW();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

## 2. 小说项目表：`novel_projects`

保存小说项目级信息和项目整体状态。

```sql
CREATE TABLE IF NOT EXISTS novel_projects (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  title TEXT NOT NULL,
  genre TEXT NOT NULL,
  audience TEXT,
  style TEXT,
  premise TEXT,

  target_total_chapters INTEGER NOT NULL DEFAULT 20 CHECK (target_total_chapters > 0),
  target_words_per_chapter INTEGER NOT NULL DEFAULT 2000 CHECK (target_words_per_chapter > 0),
  current_chapter_no INTEGER NOT NULL DEFAULT 0 CHECK (current_chapter_no >= 0),

  status TEXT NOT NULL DEFAULT 'CREATED' CHECK (status IN (
    'CREATED',
    'BIBLE_READY',
    'OUTLINE_READY',
    'WRITING',
    'REVIEWING',
    'PAUSED',
    'COMPLETED',
    'FAILED'
  )),

  error TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_novel_projects_status_updated_at
  ON novel_projects(status, updated_at DESC);

DROP TRIGGER IF EXISTS trg_novel_projects_updated_at ON novel_projects;
CREATE TRIGGER trg_novel_projects_updated_at
BEFORE UPDATE ON novel_projects
FOR EACH ROW
EXECUTE FUNCTION set_updated_at();
```

项目状态流转：

```text
CREATED -> BIBLE_READY -> OUTLINE_READY -> WRITING -> REVIEWING
       -> PAUSED
       -> COMPLETED
       -> FAILED
```


## 5. 章节正文表：`novel_chapters`

章节正文按版本保存。重写不覆盖旧稿，而是插入新版本。`is_current = true` 只表示“当前正式可续写版本”，草稿、待审稿、重写稿都不能成为 current。

```sql
CREATE TABLE IF NOT EXISTS novel_chapters (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  project_id UUID NOT NULL REFERENCES novel_projects(id) ON DELETE CASCADE,
  outline_id UUID REFERENCES novel_chapter_outlines(id) ON DELETE SET NULL,
  parent_chapter_id UUID REFERENCES novel_chapters(id) ON DELETE SET NULL,

  chapter_no INTEGER NOT NULL CHECK (chapter_no > 0),
  title TEXT,
  body TEXT,
  summary TEXT,
  word_count INTEGER NOT NULL DEFAULT 0 CHECK (word_count >= 0),

  status TEXT NOT NULL DEFAULT 'PLANNED' CHECK (status IN (
    'PLANNED',
    'GENERATING',
    'DRAFT_READY',
    'AI_REVIEWED',
    'NEED_REVIEW',
    'APPROVED',
    'PUBLISHED',
    'REWRITE_REQUESTED',
    'REJECTED',
    'FAILED'
  )),

  ai_model TEXT,
  generation_version INTEGER NOT NULL DEFAULT 1 CHECK (generation_version > 0),
  is_current BOOLEAN NOT NULL DEFAULT FALSE,
  review_token TEXT NOT NULL DEFAULT encode(gen_random_bytes(24), 'hex'),

  error TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),

  UNIQUE(project_id, chapter_no, generation_version)
);

CREATE UNIQUE INDEX IF NOT EXISTS uniq_novel_chapters_current_version
  ON novel_chapters(project_id, chapter_no)
  WHERE is_current = TRUE;

CREATE INDEX IF NOT EXISTS idx_novel_chapters_project_status
  ON novel_chapters(project_id, status, chapter_no);

CREATE INDEX IF NOT EXISTS idx_novel_chapters_project_current_approved
  ON novel_chapters(project_id, chapter_no)
  WHERE is_current = TRUE AND status IN ('APPROVED', 'PUBLISHED');

CREATE UNIQUE INDEX IF NOT EXISTS uniq_novel_chapters_review_token
  ON novel_chapters(review_token);

DROP TRIGGER IF EXISTS trg_novel_chapters_updated_at ON novel_chapters;
CREATE TRIGGER trg_novel_chapters_updated_at
BEFORE UPDATE ON novel_chapters
FOR EACH ROW
EXECUTE FUNCTION set_updated_at();
```

章节状态流转：

```text
PLANNED
  -> GENERATING
  -> DRAFT_READY
  -> AI_REVIEWED
  -> NEED_REVIEW
  -> APPROVED
  -> PUBLISHED

NEED_REVIEW -> REWRITE_REQUESTED
REWRITE_CHAPTER job -> 插入新版本 DRAFT_READY
NEED_REVIEW -> REJECTED
任意生成/审稿阶段 -> FAILED
```

续写上下文只允许读取：

```text
is_current = true
AND status IN ('APPROVED', 'PUBLISHED')
```

不能读取草稿、被拒稿、旧版本或重写失败稿。

`DRAFT_READY`、`AI_REVIEWED`、`NEED_REVIEW`、`REWRITE_REQUESTED` 一律保持 `is_current = false`。人工通过时才把该版本设为 `APPROVED + is_current = true`，并把同章其他版本设为 `is_current = false`。

## 6. 连贯性事实表：`novel_continuity_facts`

这张表防止人物、物品、能力、关系、伏笔和时间线前后矛盾。事实必须绑定章节版本。重写章节生成的新事实先保持 `PENDING`，只有人工批准新版本后才激活，避免“旧事实已失效、新版本还没通过”的中间空窗。

```sql
CREATE TABLE IF NOT EXISTS novel_continuity_facts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  project_id UUID NOT NULL REFERENCES novel_projects(id) ON DELETE CASCADE,
  chapter_id UUID REFERENCES novel_chapters(id) ON DELETE SET NULL,
  chapter_no INTEGER CHECK (chapter_no IS NULL OR chapter_no > 0),
  chapter_generation_version INTEGER,

  fact_type TEXT NOT NULL CHECK (fact_type IN (
    'character',
    'item',
    'location',
    'ability',
    'relationship',
    'foreshadowing',
    'timeline',
    'rule',
    'other'
  )),
  fact_key TEXT,
  fact_value TEXT NOT NULL,

  source TEXT NOT NULL DEFAULT 'ai' CHECK (source IN ('ai', 'human', 'import', 'system')),
  confidence NUMERIC NOT NULL DEFAULT 0.8 CHECK (confidence >= 0 AND confidence <= 1),
  status TEXT NOT NULL DEFAULT 'PENDING' CHECK (status IN (
    'ACTIVE',
    'PENDING',
    'INACTIVE'
  )),
  superseded_by UUID REFERENCES novel_continuity_facts(id) ON DELETE SET NULL,

  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_novel_continuity_facts_active_project
  ON novel_continuity_facts(project_id, fact_type, created_at DESC)
  WHERE status = 'ACTIVE';

CREATE INDEX IF NOT EXISTS idx_novel_continuity_facts_chapter_id
  ON novel_continuity_facts(chapter_id);
```

生成或审稿第 N 章时，只读取已激活事实，并排除同章旧 AI facts。这样重写第 3 章时不会被第 3 章旧版本 facts 误判；人工锁定事实仍然保留。

```sql
SELECT fact_type, fact_key, fact_value
FROM novel_continuity_facts
WHERE project_id = $1
  AND status = 'ACTIVE'
  AND (
    chapter_no IS NULL
    OR chapter_no < $2
    OR source = 'human'
  )
ORDER BY created_at DESC
LIMIT 80;
```

重写生成新版本时，新事实先写为 `PENDING`：

```sql
INSERT INTO novel_continuity_facts (
  project_id,
  chapter_id,
  chapter_no,
  chapter_generation_version,
  fact_type,
  fact_key,
  fact_value,
  source,
  confidence,
  status
)
VALUES (
  $1, $2, $3, $4, $5, $6, $7, 'ai', COALESCE($8::numeric, 0.8), 'PENDING'
);
```

人工批准新版本后，再切换同章事实：

```sql
UPDATE novel_continuity_facts
SET status = 'INACTIVE'
WHERE project_id = $1
  AND chapter_no = $2
  AND chapter_id IS DISTINCT FROM $3
  AND source = 'ai'
  AND status IN ('ACTIVE', 'PENDING');

UPDATE novel_continuity_facts
SET status = 'ACTIVE'
WHERE chapter_id = $3
  AND source = 'ai'
  AND status = 'PENDING';
```

人工锁定的事实可以用 `source = 'human'` 且 `status = 'ACTIVE'`，默认不被自动重写失效。

## 7. 审稿报告表：`novel_review_reports`

AI 审稿只生成报告，不直接最终批准。

```sql
CREATE TABLE IF NOT EXISTS novel_review_reports (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  project_id UUID NOT NULL REFERENCES novel_projects(id) ON DELETE CASCADE,
  chapter_id UUID NOT NULL REFERENCES novel_chapters(id) ON DELETE CASCADE,
  ai_run_id UUID,

  consistency_score INTEGER CHECK (consistency_score BETWEEN 0 AND 100),
  readability_score INTEGER CHECK (readability_score BETWEEN 0 AND 100),
  plot_score INTEGER CHECK (plot_score BETWEEN 0 AND 100),
  commercial_score INTEGER CHECK (commercial_score BETWEEN 0 AND 100),
  total_score INTEGER CHECK (total_score BETWEEN 0 AND 100),

  issues JSONB NOT NULL DEFAULT '[]'::jsonb,
  suggestions JSONB NOT NULL DEFAULT '[]'::jsonb,
  verdict TEXT NOT NULL DEFAULT 'MANUAL_REVIEW' CHECK (verdict IN (
    'PASS',
    'REWRITE',
    'MANUAL_REVIEW'
  )),

  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_novel_review_reports_chapter_created_at
  ON novel_review_reports(chapter_id, created_at DESC);

CREATE INDEX IF NOT EXISTS idx_novel_review_reports_ai_run_id
  ON novel_review_reports(ai_run_id);
```

`ai_run_id` 在 `novel_ai_runs` 创建后再补外键约束，避免建表顺序循环依赖。

建议规则：

```text
total_score >= 80 且 verdict = PASS
  -> 章节进入 NEED_REVIEW，等待人工确认

total_score < 80 或 verdict = REWRITE
  -> 章节进入 NEED_REVIEW，页面默认提示建议重写

无论 AI 是否通过，都不直接进入 APPROVED
```

## 8. 人工审核记录表：`novel_human_reviews`

记录每一次人工操作，解决“谁点了通过、为什么要求重写、人工意见是什么、第几次重写”的追踪问题。

```sql
CREATE TABLE IF NOT EXISTS novel_human_reviews (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  project_id UUID NOT NULL REFERENCES novel_projects(id) ON DELETE CASCADE,
  chapter_id UUID NOT NULL REFERENCES novel_chapters(id) ON DELETE CASCADE,

  action TEXT NOT NULL CHECK (action IN (
    'APPROVE',
    'REQUEST_REWRITE',
    'REJECT',
    'PAUSE_PROJECT'
  )),
  comment TEXT,
  reviewer TEXT NOT NULL DEFAULT 'local_user',

  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_novel_human_reviews_chapter_created_at
  ON novel_human_reviews(chapter_id, created_at DESC);

CREATE INDEX IF NOT EXISTS idx_novel_human_reviews_project_created_at
  ON novel_human_reviews(project_id, created_at DESC);
```

人工点“要求重写”时，把修改意见同时写入 `novel_human_reviews.comment` 和 `REWRITE_CHAPTER` 的 `payload`。

## 9. 项目操作记录表：`novel_project_events`

记录项目级人工管理动作，解决“谁改了设定集、谁改了大纲、为什么暂停项目、什么时候恢复”的追踪问题。

```sql
CREATE TABLE IF NOT EXISTS novel_project_events (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id UUID NOT NULL REFERENCES novel_projects(id) ON DELETE CASCADE,
  bible_id UUID REFERENCES novel_bibles(id) ON DELETE SET NULL,

  chapter_id UUID REFERENCES novel_chapters(id) ON DELETE SET NULL,

    'BIBLE_UPDATED',
    'OUTLINE_UPDATED',
    'PROJECT_TARGET_UPDATED',
    'PROJECT_PAUSED',
    'PROJECT_RESUMED'
  )),
  actor TEXT NOT NULL DEFAULT 'local_user',
  comment TEXT,
  before_payload JSONB NOT NULL DEFAULT '{}'::jsonb,
  after_payload JSONB NOT NULL DEFAULT '{}'::jsonb,

```

## 10. 任务队列表：`novel_generation_jobs`

n8n 用任务表调度生成、审稿和重写。所有工作流都必须原子领取任务。

```sql
CREATE TABLE IF NOT EXISTS novel_generation_jobs (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  project_id UUID NOT NULL REFERENCES novel_projects(id) ON DELETE CASCADE,
  chapter_id UUID REFERENCES novel_chapters(id) ON DELETE SET NULL,

  job_type TEXT NOT NULL CHECK (job_type IN (
    'GENERATE_BIBLE',
    'GENERATE_BIBLE_PATCH',
    'GENERATE_OUTLINE',
    'PLAN_CHAPTER_DIRECTOR',
    'GENERATE_CHAPTER',
    'REVIEW_CHAPTER',
    'REWRITE_CHAPTER',
    'NOTIFY_REVIEW'
  )),
  chapter_no INTEGER CHECK (chapter_no IS NULL OR chapter_no > 0),
  payload JSONB NOT NULL DEFAULT '{}'::jsonb,

  status TEXT NOT NULL DEFAULT 'PENDING' CHECK (status IN (
    'PENDING',
    'RUNNING',
    'SUCCEEDED',
    'FAILED',
    'CANCELLED'
  )),

  attempt_count INTEGER NOT NULL DEFAULT 0 CHECK (attempt_count >= 0),
  max_attempts INTEGER NOT NULL DEFAULT 3 CHECK (max_attempts > 0),
  error_message TEXT,

  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  started_at TIMESTAMPTZ,
  finished_at TIMESTAMPTZ,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_novel_generation_jobs_status_type_created_at
  ON novel_generation_jobs(status, job_type, created_at);

CREATE UNIQUE INDEX IF NOT EXISTS uniq_novel_jobs_project_level
  ON novel_generation_jobs(project_id, job_type)
  WHERE chapter_no IS NULL
    AND status IN ('PENDING', 'RUNNING');

CREATE UNIQUE INDEX IF NOT EXISTS uniq_novel_jobs_chapter_level
  ON novel_generation_jobs(
    project_id,
    job_type,
    chapter_no,
    COALESCE(chapter_id, '00000000-0000-0000-0000-000000000000'::uuid)
  )
  WHERE chapter_no IS NOT NULL
    AND status IN ('PENDING', 'RUNNING');

DROP TRIGGER IF EXISTS trg_novel_generation_jobs_updated_at ON novel_generation_jobs;
CREATE TRIGGER trg_novel_generation_jobs_updated_at
BEFORE UPDATE ON novel_generation_jobs
FOR EACH ROW
EXECUTE FUNCTION set_updated_at();
```

项目级任务用 `chapter_no IS NULL` 去重，例如 `GENERATE_BIBLE`、`GENERATE_BIBLE_PATCH`、`GENERATE_OUTLINE`。章节级任务按 `chapter_id` 细化去重，避免第 3 章 v1 和第 3 章 v2 的 `REVIEW_CHAPTER` 互相冲突。

## 11. AI 调用日志表：`novel_ai_runs`

记录每次 GLM 调用的请求、原始响应、解析结果和错误，避免只能去 n8n 执行历史里翻排查记录。

```sql
CREATE TABLE IF NOT EXISTS novel_ai_runs (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  project_id UUID REFERENCES novel_projects(id) ON DELETE CASCADE,
  chapter_id UUID REFERENCES novel_chapters(id) ON DELETE SET NULL,
  job_id UUID REFERENCES novel_generation_jobs(id) ON DELETE SET NULL,

  run_type TEXT NOT NULL CHECK (run_type IN (
    'GENERATE_BIBLE',
    'GENERATE_BIBLE_PATCH',
    'GENERATE_OUTLINE',
    'PLAN_CHAPTER_DIRECTOR',
    'GENERATE_CHAPTER',
    'REVIEW_CHAPTER',
    'REWRITE_CHAPTER'
  )),
  model TEXT,
  prompt_version TEXT,

  request_payload JSONB NOT NULL DEFAULT '{}'::jsonb,
  response_payload JSONB NOT NULL DEFAULT '{}'::jsonb,
  parsed_payload JSONB NOT NULL DEFAULT '{}'::jsonb,

  success BOOLEAN NOT NULL DEFAULT TRUE,
  error_message TEXT,

  started_at TIMESTAMPTZ,
  finished_at TIMESTAMPTZ,
  duration_ms INTEGER CHECK (duration_ms IS NULL OR duration_ms >= 0),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_novel_ai_runs_project_created_at
  ON novel_ai_runs(project_id, created_at DESC);

CREATE INDEX IF NOT EXISTS idx_novel_ai_runs_chapter_created_at
  ON novel_ai_runs(chapter_id, created_at DESC);

CREATE INDEX IF NOT EXISTS idx_novel_ai_runs_job_id
  ON novel_ai_runs(job_id);

DO $$
BEGIN
  IF NOT EXISTS (
    SELECT 1
    FROM pg_constraint
    WHERE conname = 'fk_novel_review_reports_ai_run'
  ) THEN
    ALTER TABLE novel_review_reports
      ADD CONSTRAINT fk_novel_review_reports_ai_run
      FOREIGN KEY (ai_run_id)
      REFERENCES novel_ai_runs(id)
      ON DELETE SET NULL;
  END IF;
END $$;
```

每个 GLM 工作流都应在 HTTP Request 后写入一条 `novel_ai_runs`。解析失败也要记录 `response_payload` 和 `error_message`，再把对应任务按失败规则处理。`started_at`、`finished_at`、`duration_ms` 用来排查 Bible、章节生成、审稿和重写哪个环节最慢。

## 11. 任务领取和完成 SQL

n8n 用任务表调度生成、审稿和重写。所有工作流都必须原子领取任务。

原子领取任务 SQL 模板：

```sql
WITH claimed AS (
  SELECT id
  FROM novel_generation_jobs
  WHERE job_type = $1
    AND status = 'PENDING'
    AND attempt_count < max_attempts
  ORDER BY created_at ASC
  FOR UPDATE SKIP LOCKED
  LIMIT 1
)
UPDATE novel_generation_jobs j
SET
  status = 'RUNNING',
  started_at = NOW(),
  attempt_count = attempt_count + 1,
  updated_at = NOW()
FROM claimed
WHERE j.id = claimed.id
RETURNING j.*;
```

任务成功：

```sql
UPDATE novel_generation_jobs
SET status = 'SUCCEEDED',
    finished_at = NOW(),
    updated_at = NOW()
WHERE id = $1;
```

任务失败：

```sql
UPDATE novel_generation_jobs
SET status = CASE
      WHEN attempt_count >= max_attempts THEN 'FAILED'
      ELSE 'PENDING'
    END,
    error_message = $2,
    finished_at = CASE
      WHEN attempt_count >= max_attempts THEN NOW()
      ELSE finished_at
    END,
    updated_at = NOW()
WHERE id = $1;
```

- “导出全文 Markdown”只导出当前正式且已批准或已发布的章节版本。

项目控制台提供前端生成入口和安全 POST 操作：

- “立即生成设定集”在存在 `GENERATE_BIBLE(PENDING)` 时显示，提交到 `POST /webhook/novel-generate-bible-now`。12 号 workflow 只领取当前项目的待处理设定集任务，直接调用 GLM，写入设定集并创建大纲任务。
- “立即生成扩写设定补丁”在存在 `GENERATE_BIBLE_PATCH(PENDING)` 时显示，提交到 `POST /webhook/novel-generate-bible-patch-now`。12 号 workflow 会读取扩写计划、当前设定集、已批准正文和事实库，生成待确认补丁，不直接改正文或事实库。
- “立即生成大纲”在存在 `GENERATE_OUTLINE(PENDING)` 时显示，提交到 `POST /webhook/novel-generate-outline-now`。13 号 workflow 只领取当前项目的待处理大纲任务，直接调用 GLM，写入章节目录并创建第 1 章生成任务。
- “排队下一步”提交到 `POST /webhook/novel-project-continue`。它只创建下一步应执行的队列任务；有待审、失败、运行中或待处理任务时会阻止继续写作。
- “申请重写此章”提交到 `POST /webhook/novel-chapter-rewrite-request`。它只允许当前正式版本触发，旧正式版本保持 current，不会覆盖正文。
- “重新发送提醒”提交到 `POST /webhook/novel-review-remind`。它只为待人工审核章节创建通知任务，提醒链接只进入审核详情页。
- “编辑设定集”提交到 `POST /webhook/novel-bible-update`，后续生成读取新的设定集。
- “确认扩写设定补丁”提交到 `POST /webhook/novel-bible-patch-action`，只把新增人物、组织势力、地点、关系和剧情约束合并进 `novel_bibles`，后续大纲、导演台和正文才会读取这些新增设定。
- “编辑本章大纲”提交到 `POST /webhook/novel-outline-update`，后续生成读取新的章节大纲。
- “修改项目目标与扩写计划”提交到 `POST /webhook/novel-project-targets-update`，目标章节数不能小于当前进度；扩写剧情要求会进入后续 prompt，并在已有设定集时先创建扩写设定补丁任务。
- “暂停 / 恢复项目”提交到 `POST /webhook/novel-project-status-toggle`，暂停项目会被队列领取 SQL 跳过。
- “手动编辑正文”提交到 `POST /webhook/novel-chapter-manual-edit`，只创建新的候选版本并进入智能审稿，不覆盖当前正式版本。
- “归档 / 恢复项目”提交到 `POST /webhook/novel-project-archive-toggle`。归档是软删除，会取消待处理任务并让队列跳过该项目；恢复后需手动继续写作。

上述人工管理动作都会写入 `novel_project_events`。正文编辑必须走“候选版本 -> AI 审稿 -> 人工通过”；删除项目当前实现为归档软删除，不做物理删除。

创建项目动作完成后返回中文结果页，不直接把接口 JSON 暴露给浏览器用户。结果页说明“待生成设定集”表示任务已排队但内容尚未生成，并提供“立即生成设定集”“查看项目控制台”“查看队列”“查看项目列表”“返回工作台”等入口；所有状态和任务类型按中文展示。

## 节点结构


## 原子插入新章节版本

章节版本插入必须是原子操作。不要在 n8n 里分散计算版本号和插入新版本，否则并发重写时容易出现版本号冲突或候选稿覆盖关系混乱。

推荐做成 PostgreSQL 函数，让 n8n 只调用一次：

```sql
CREATE OR REPLACE FUNCTION create_novel_chapter_version(
  p_project_id UUID,
  p_outline_id UUID,
  p_parent_chapter_id UUID,
  p_chapter_no INTEGER,
  p_title TEXT,
  p_body TEXT,
  p_summary TEXT,
  p_word_count INTEGER,
  p_ai_model TEXT,
  p_status TEXT DEFAULT 'DRAFT_READY',
  p_make_current BOOLEAN DEFAULT FALSE
)
RETURNS novel_chapters AS $$
DECLARE
  v_version INTEGER;
  v_row novel_chapters%ROWTYPE;
BEGIN
  PERFORM pg_advisory_xact_lock(hashtext(p_project_id::text), p_chapter_no);

  SELECT COALESCE(MAX(generation_version), 0) + 1
  INTO v_version
  FROM novel_chapters
  WHERE project_id = p_project_id
    AND chapter_no = p_chapter_no;

  IF p_make_current THEN
    UPDATE novel_chapters
    SET is_current = FALSE
    WHERE project_id = p_project_id
      AND chapter_no = p_chapter_no
      AND is_current = TRUE;
  END IF;

  INSERT INTO novel_chapters (
    project_id,
    outline_id,
    parent_chapter_id,
    chapter_no,
    title,
    body,
    summary,
    word_count,
    status,
    ai_model,
    generation_version,
    is_current
  )
  VALUES (
    p_project_id,
    p_outline_id,
    p_parent_chapter_id,
    p_chapter_no,
    p_title,
    p_body,
    p_summary,
    COALESCE(p_word_count, 0),
    p_status,
    p_ai_model,
    v_version,
    p_make_current
  )
  RETURNING * INTO v_row;

  RETURN v_row;
END;
$$ LANGUAGE plpgsql;
```

n8n 调用示例：

```sql
SELECT *
FROM create_novel_chapter_version(
  $1::uuid,
  $2::uuid,
  NULLIF($3, '')::uuid,
  $4::integer,
  $5,
  $6,
  $7,
  COALESCE($8::integer, 0),
  $9,
  'DRAFT_READY',
  FALSE
);
```

生成章节或重写章节都传 `FALSE`：生成成功只是产生一个候选版本，不抢 current。人工通过时才设置 `is_current = true`。

## 人工通过 SQL

```sql
WITH candidate AS (
  SELECT *
  FROM novel_chapters
  WHERE id = $1::uuid
    AND review_token = $2
    AND status = 'NEED_REVIEW'
  FOR UPDATE
), disable_current AS (
  UPDATE novel_chapters c
  SET is_current = FALSE
  FROM candidate a
  WHERE c.project_id = a.project_id
    AND c.chapter_no = a.chapter_no
    AND c.id <> a.id
    AND c.is_current = TRUE
  RETURNING c.*
), disable_complete AS (
  SELECT 1 AS ok FROM disable_current
  UNION ALL
  SELECT 1 AS ok
  WHERE NOT EXISTS (SELECT 1 FROM disable_current)
  LIMIT 1
), approved AS (
  UPDATE novel_chapters c
  SET
    status = 'APPROVED',
    is_current = TRUE
  FROM candidate a, disable_complete
  WHERE c.id = a.id
  RETURNING *
), human_review AS (
  INSERT INTO novel_human_reviews (
    project_id,
    chapter_id,
    action,
    comment,
    reviewer
  )
  SELECT
    project_id,
    id,
    'APPROVE',
    NULLIF($3, ''),
    COALESCE(NULLIF($4, ''), 'local_user')
  FROM approved
  RETURNING *
), inactive_old_facts AS (
  UPDATE novel_continuity_facts f
  SET status = 'INACTIVE'
  FROM approved a
  WHERE f.project_id = a.project_id
    AND f.chapter_no = a.chapter_no
    AND f.chapter_id IS DISTINCT FROM a.id
    AND f.source = 'ai'
    AND f.status IN ('ACTIVE', 'PENDING')
  RETURNING f.*
), active_new_facts AS (
  UPDATE novel_continuity_facts f
  SET status = 'ACTIVE'
  FROM approved a
  WHERE f.chapter_id = a.id
    AND f.source = 'ai'
    AND f.status = 'PENDING'
  RETURNING f.*
), project AS (
  UPDATE novel_projects p
  SET
    current_chapter_no = GREATEST(current_chapter_no, approved.chapter_no),
    status = CASE
      WHEN approved.chapter_no >= p.target_total_chapters THEN 'COMPLETED'
      ELSE 'WRITING'
    END
  FROM approved
  WHERE p.id = approved.project_id
  RETURNING p.*, approved.chapter_no AS approved_chapter_no
), next_job AS (
  INSERT INTO novel_generation_jobs (project_id, job_type, chapter_no, status)
  SELECT id, 'GENERATE_CHAPTER', approved_chapter_no + 1, 'PENDING'
  FROM project
  WHERE approved_chapter_no < target_total_chapters
  ON CONFLICT DO NOTHING
  RETURNING *
)
SELECT
  approved.*,
  (SELECT id FROM next_job LIMIT 1) AS next_job_id
FROM approved;
```

# 十二、n8n 工作流 18：小说任务自动恢复

## 目标

参考现有 `10_auto_recovery_workflow.json`，扫描卡住的小说任务。

## 恢复规则

```text
RUNNING 超过 10 分钟的 GENERATE_BIBLE / GENERATE_OUTLINE
  -> attempt_count 未达 max_attempts：回到 PENDING
  -> 达上限：FAILED，并写 error_message

RUNNING 超过 20 分钟的 GENERATE_CHAPTER / REWRITE_CHAPTER / REVIEW_CHAPTER
  -> attempt_count 未达 max_attempts：回到 PENDING
  -> 达上限：FAILED，并按任务类型处理章节状态
```

失败状态处理：

```text
GENERATE_CHAPTER 失败：
  只更新 job failed，因为章节候选版本尚未创建。

REVIEW_CHAPTER 失败：
  更新对应 chapter 为 FAILED，便于审核中心展示错误。

REWRITE_CHAPTER 失败：
  原章节保持 REWRITE_REQUESTED，在 job.error_message 里记录失败原因，方便人工重新触发。
```

## 扫描 SQL 示例

```sql
UPDATE novel_generation_jobs
SET
  status = CASE
    WHEN attempt_count >= max_attempts THEN 'FAILED'
    ELSE 'PENDING'
  END,
  error_message = CASE
    WHEN attempt_count >= max_attempts THEN '任务超时且达到最大重试次数'
    ELSE error_message
  END,
  finished_at = CASE
    WHEN attempt_count >= max_attempts THEN NOW()
    ELSE finished_at
  END,
  updated_at = NOW()
WHERE status = 'RUNNING'
  AND started_at < NOW() - INTERVAL '20 minutes'
RETURNING *;
```

达最大重试次数后，同步失败到审稿中的章节：

```sql
UPDATE novel_chapters c
SET
  status = 'FAILED',
  error = j.error_message
FROM novel_generation_jobs j
WHERE c.id = j.chapter_id
  AND j.status = 'FAILED'
  AND j.job_type = 'REVIEW_CHAPTER'
  AND c.status IN ('DRAFT_READY', 'AI_REVIEWED', 'NEED_REVIEW');
```

`REWRITE_CHAPTER` 失败不直接把原章节改成 `FAILED`，因为原章节是人工要求重写的审核对象；保留 `REWRITE_REQUESTED` 能让审核中心继续展示人工意见和失败原因。

## 补齐下一章任务

人工通过 SQL 已经把“批准章节”和“创建下一章任务”合并在同一条 CTE 里。自动恢复工作流仍建议保留一个兜底修复：如果项目处于 `WRITING`，当前章节未完结，但下一章生成任务缺失，则补建任务。

```sql
INSERT INTO novel_generation_jobs (project_id, job_type, chapter_no, status)
SELECT
  p.id,
  'GENERATE_CHAPTER',
  p.current_chapter_no + 1,
  'PENDING'
FROM novel_projects p
WHERE p.status = 'WRITING'
  AND p.current_chapter_no < p.target_total_chapters
  AND NOT EXISTS (
    SELECT 1
    FROM novel_generation_jobs j
    WHERE j.project_id = p.id
      AND j.job_type = 'GENERATE_CHAPTER'
      AND j.chapter_no = p.current_chapter_no + 1
      AND j.status IN ('PENDING', 'RUNNING')
  )
ON CONFLICT DO NOTHING;
```

# 十六、测试与验收清单

## 文档自检

- 表名统一使用 `novel_*`。
- 所有状态值在表定义、工作流说明和 SQL 示例里保持一致。
- AI 审稿不会直接把章节改成 `APPROVED`。
- Server 酱只提醒，不替代小说审核中心。
- `is_current = true` 只表示当前正式可续写版本；草稿、待审稿、重写稿都保持 `is_current = false`。

## SQL 可落地性检查

- 迁移 SQL 使用 `CREATE TABLE IF NOT EXISTS`、`CREATE INDEX IF NOT EXISTS`。
- 已存在表调整时使用 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 和 `DO $$ ... $$` 包装约束添加。
- 任务领取使用 `FOR UPDATE SKIP LOCKED`，不使用 `SELECT pending LIMIT 1` 后再单独 UPDATE。
- `novel_generation_jobs` 的唯一约束拆成项目级和章节级；章节级任务包含 `chapter_id`，支持同章多版本审稿/重写。
- 章节版本写入使用 `create_novel_chapter_version(...)` 或等价单事务函数，不能拆成多个 n8n 节点。
- `review_token` 使用唯一索引，审核操作必须能唯一定位候选章节。

## 工作流一致性检查

- 每个生成工作流都有：领取任务、读取上下文、调用 GLM、记录 `novel_ai_runs`、解析 JSON、写业务表、写任务成功/失败。
- 任务失败时写入 `error_message`，达到最大重试次数后进入 `FAILED`。
- 项目和章节状态都能从审核页面看出当前卡在哪一步。
- 审核动作必须走 `POST /webhook/novel-review-action`，并校验 `chapter_id + review_token`。
- 每次人工通过、要求重写、拒绝或暂停都必须写入 `novel_human_reviews`。

## 章节续写检查

- 第 2 章只能读取第 1 章 `is_current = true` 且 `status IN ('APPROVED', 'PUBLISHED')` 的摘要。
- 不能读取 `DRAFT_READY`、`NEED_REVIEW`、`REWRITE_REQUESTED`、`REJECTED`、`FAILED` 或旧版本章节。
- 生成/审稿第 N 章时必须带上 `status = 'ACTIVE'` 且 `chapter_no < N OR source = 'human'` 的 continuity facts。

## 重写检查

- 重写生成新版本，不覆盖旧正文。
- 新版本插入使用原子函数，默认 `is_current = false`。
- 人工通过新版本时，才设置该版本 `APPROVED + is_current = true`，并关闭同章其他 current。
- 重写新版本 facts 先写为 `PENDING`，旧版本 facts 在新版本人工通过前保持 `ACTIVE`。
- 新版本人工通过后，旧版本 AI facts 变为 `INACTIVE`，新版本 AI facts 变为 `ACTIVE`。
- 新版本仍然进入 AI 审稿和人工审核，不能跳过审核。
